## 1. Landslide data — TWO different sources were uploaded, not one

### 1a. `Global_Landslide_Catalog_Export_rows.csv`
- This is **NASA's Global Landslide Catalog (GLC)** — a global, crowd/media-sourced
  catalog. It is **not** the GSI inventory.
- 11,033 rows total, 31 columns, UTF-8 CSV.
- Key columns: `event_date` (string, `MM/DD/YYYY HH:MM:SS AM/PM`), `event_time`,
  `longitude`, `latitude` (both plain decimal degrees, presumed WGS84 — CRS is not
  stated in the file), `country_name`, `admin_division_name`, `landslide_trigger`,
  `landslide_category`, `fatality_count`, etc.
- Only **1,265 rows are India**, and NER-state rows within that are sparse
  (roughly a few hundred total across all 8 states combined) and use inconsistent
  spellings, some with diacritics: `Nāgāland`, `Arunāchal Pradesh`, `Meghālaya`,
  alongside plain `Nagaland`, `Arunachal Pradesh`, `Meghalaya`. These need
  normalizing before filtering.
- Date range: 1997–2016.

### 1b. `landslide_report.pdf`
- This is a **field-validated, India-specific landslide inventory** (title on
  page 1: "LANDSLIDE INVENTORY (Field validated)"), organized as a clean table:
  `Sl.No, Slide_No, State, District, Slide_Name, NH_SH_Location, Latitude,
  Longitude, Material Involved, Movement Type, History`.
- 904 pages, **36,071 records**, all-India, extractable cleanly with
  `pdfplumber` (verified — every page is one consistent 11-column table).
- All 8 NER states are present in a sampled check (every 15th page):
  Mizoram, Manipur, Nagaland, Arunachal Pradesh, Assam, Meghalaya, Sikkim,
  Tripura all appear. Full exhaustive counts need a full-PDF pass (Phase 2).
- Coordinates are plain decimal `Latitude`/`Longitude` columns — CRS not
  stated, presumed WGS84 (standard for GPS-collected points).
- **The `NH_SH_Location` column shows this inventory is built around National
  Highway / State Highway corridors** — it is likely a road-safety landslide
  inventory (GSI/BRO/NHIDCL style), not a uniform regional census. This is a
  real spatial sampling bias to account for later (landslides are systematically
  over-represented near highways).
- **The `History` column is not a clean event-date field.** It's free text:
  clean dates (`17 May 2016`), bare years (`2015`), ranges with times
  (`2nd to 8th August 2023, 23 August 2023`), and `NA` (a large fraction).
  Only entries with a clean parseable date can be used for rainfall temporal
  matching — the rest either need a fallback strategy or must be dropped from
  the rainfall-feature part of training (they can still be used for
  spatial-only features).
- Dates span up to August 2025 — well past the 2007–2016 rainfall window
  you downloaded. Any record without rainfall coverage for its date can't get
  rainfall features and would need separate handling.

### Recommendation
Given the mismatch, **`landslide_report.pdf` looks like it's meant to be your
primary "GSI-style" ground truth** — it's India-specific, far larger, and
field-validated, versus the sparse global GLC csv. I'd suggest using the PDF as
the primary source and the CSV only as an optional cross-check/supplement. But
this is your call, since I can't confirm which one you intended as "the GSI
inventory" — please confirm before I filter to NER in Phase 2, since it changes
the whole downstream pipeline.
